# Contributing

- `docs/spec.md` is authoritative. Change the spec first, then the schema and validator, then the tests.
- `npm test` and `npm run lint` must pass. CI runs both on Node 20 and 22.
- Fixtures in `test/fixtures/*.json5` double as documentation images. After an intended render change run `npm run update-snapshots` and `npm run docs`, and commit the changed SVGs (both styles).
- The JSON Schema check runs from `lib/generated/validate-schema.js`, generated by `scripts/build-validator.js` (ajv standalone, so the browser bundle needs no ajv and no `new Function`). It is git-ignored and rebuilt by `npm ci` (prepare), `npm test`, `npm run lint` and `npm run build`; run `npm run build-validator` after editing the schema. ajv is a devDependency. The published package includes the generated file.
- Glyph outlines in `lib/glyphs.js` are generated from Bravura by `scripts/extract-glyphs.js`. Keep `NOTICE-BRAVURA.txt` in step with the source version.
- Every fenced `json5 drumdrom` block in the docs is tested. Use `json5 drumdrom-invalid` with a `// expect: E_CODE` comment for examples that must fail.
- Style: CommonJS with `'use strict'`, snake_case keys, kebab-case file names, camelCase functions. Keep comments sparse. Do not use em dashes in comments or docs.
- Versioning follows Semantic Versioning 2.0.0. Record changes in `CHANGELOG.md`.
